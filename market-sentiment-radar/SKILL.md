# 市场情绪雷达 Skill 1.0

## 核心原则

**采集阶段只负责把原始材料和时间记好；分析阶段再结合关键 K 线清洗、归类、对齐和解释。**

不要在采集时过度加工，也不要因为时间不完整而放弃收集。时间字段必须诚实保留：页面显示绝对时间就原样记录；只显示“34分钟前”等相对时间，就同时记录采集时间并保留原始显示，不得伪造精确发帖时间。

情绪分析是交易辅助，不可单独确认顶部/底部；评论数量不等于真实资金、仓位或全市场情绪。

## 工作流程

### 阶段 A：先采集原始记录

1. 明确本次观察的市场、标的/指数、讨论区与大致事件背景；不要求采集时就先确定最终分析结论。
2. 选择最相关的 2—4 个来源。按目标参与者与事件灵活选择，不为平台数量而采集。
3. 每条记录尽可能保存：
   - 平台、讨论区/频道
   - 原始用户名（分析报告默认隐藏）
   - 页面显示的发帖时间原文
   - 页面显示的绝对时间（若有）
   - 本次采集时间，统一用 ISO 8601 并注明时区
   - 原话全文或明确标注的摘录
   - 原帖链接
   - 标的/话题
4. 不在采集阶段强行判断情绪、买卖意图或时间曲线。可选做简单标签，但必须保留原始记录。
5. 页面只显示相对时间时，保存如“34分钟前”的原文和采集时间；只有确认采集时间与页面显示严格对应，后续才可计算近似时间，并标记为推算值。若无法确认，就留空/标记待核实。
6. 不绕过登录、访问控制或平台规则。微信群等私域内容只处理用户有权访问并主动提供/授权的材料。

### 阶段 B：事件发生后再整理分析

1. 用户指定关键 K 线，或根据行情数据识别关键事件：急跌、急拉、长下影、放量反包、跌破前低、二探、重大公告、宏观事件、Crypto 清算/资金费率异常等。
2. 以关键事件为中心确定时间窗口。A 股可先看事件前后各 1 个交易日，必要时扩展到前后 3—5 日；二探研究可延伸到后续 1—8 周。Crypto 按事件前后小时/天切片。
3. 复制原始数据到分析层，不覆盖原始文件。先检查重复、缺失时间、摘录/截断、异常时间、重复作者和来源分布。
4. 再对每条记录做情绪和行为标签；明确区分“看多/看空”与“买入/持有/减仓/退出/观望”。例如“看多但回本就卖”是看多表达加退出意愿。
5. 将帖子时间与 K 线、成交额、涨跌家数、行业相对强弱、新闻/公告时间对齐。
6. 按样本量选择 5 分钟、15 分钟、小时或交易阶段聚合。数据稀疏时不要硬画分钟曲线。
7. 比较关键节点前后：发帖量、独立作者数、情绪构成、行为意愿、来源构成，以及时间可用率是否变化。
8. 输出简洁的交易结论：情绪现状、变化方向、潜在买卖盘行为、证据强弱、下一步需要观察什么。不得仅凭情绪给出确定买卖指令。

## 来源选择目录（按任务挑选）

### A 股
- **雪球**：个股/指数讨论区、关注者讨论、热门帖评论。观察持仓者态度、叙事和反弹是否被相信；注意相对时间、重复观点和强意见偏差。
- **东方财富股吧**：个股、指数、ETF 讨论区。观察割肉、回本、抄底、追涨意愿；噪声和夸大仓位较多。
- **淘股吧**：短线交易、题材、连板、情绪周期；用户偏短线，不能代表全部投资者。
- **微博、抖音、B站公开内容**：观察热门叙事扩散；注意推荐算法、评论排序与传播偏差。
- **财经新闻评论、券商/上市公司互动平台**：用于识别催化剂和预期变化；新闻本身不等于散户情绪。
- **行情侧辅助数据**：指数/个股 OHLCV、成交额、涨跌家数、涨停跌停、ETF 份额/成交、融资融券、行业相对强弱。

### Crypto
- **X/Twitter**：项目叙事、KOL 观点、FOMO/FUD 与公告传播；识别机器人、刷屏、推广和转发。
- **Telegram/Discord 公开社区**：观察社区信心。私群只处理用户明确提供且有权分析的导出，不绕过权限。
- **Reddit**：长讨论、反对意见和用户经验；区分帖子、评论与 subreddit。
- **项目论坛、治理论坛、官方公告频道**：区分官方信息与社区情绪。
- **交易所广场/社区动态**：仅在可访问、规则允许、可保留原帖链接与时间时使用。
- **市场与链上数据**：价格、成交量、资金费率、未平仓量、清算、盘口、资金流、持币集中度，用来验证文字情绪是否有交易行为支撑。

### 微信群与私域
- 仅分析用户有权访问并主动提供/授权的导出或截图。
- 默认对群成员去标识化。
- 截图无时间戳时，标记时间精度不足，不推断分钟。

## 数据格式

采集层尽量保留以下字段：

| 字段 | 用途 |
|---|---|
| record_id | 稳定记录 ID |
| platform | 平台 |
| board_or_channel | 讨论区/频道/群名称 |
| username_raw | 原用户名，报告默认隐藏 |
| posted_at_raw | 页面原始时间显示 |
| posted_at_iso | 仅在来源提供绝对时间或可靠核验后填写 |
| collected_at_iso | 实际采集时间，含时区 |
| time_precision | second/minute/hour/date/relative/unknown |
| time_verification | source_page/api/crawl_timestamp/estimated/unverified |
| symbol_or_topic | 相关指数、股票、币或事件 |
| text_raw | 原话，不能静默改写 |
| text_excerpt_flag | 是否为摘录/截断 |
| post_url | 原帖链接 |
| duplicate_group | 重复/转发分组 |
| quality_flag | normal/duplicate/truncated/time_unverified/off_topic 等 |

分析层追加：
- emotion_primary / emotion_secondary
- direction：bullish/bearish/neutral/mixed/unclear
- behavior_intent：buy_dip/add/hold/trim/exit/short/hedge/wait/fomo/regret/unknown
- intensity：0—3，作为人工标注，不是客观心理测量
- evidence_note：文本证据
- event_phase：事件前/急跌中/插针/首轮反弹/二探/确认后/未知

## 情绪标签字典

1. fear_panic：恐慌、害怕、极端不安
2. capitulation_loss：割肉、认亏、绝望、持仓受伤
3. skeptical_bounce：认为反弹是诱多/下跌中继
4. cautious_wait：等确认、不敢买、等待回踩
5. dip_buying：明确抄底或分批买入
6. bullish_reversal：相信反转、看多延续
7. fomo_chasing：害怕踏空、追涨、梭哈
8. relief_breakeven_exit：回本就走、借反弹减仓
9. frustration_blame：抱怨、指责市场或机构
10. euphoria_greed：暴富想象、过度自信、无条件看涨
11. neutral_information：资讯、行情转述、无明显情绪
12. unclear_irony：讽刺、反话、上下文不足

情绪方向与行为意愿必须分开。例如“看多但准备卖出”不能只归为看多。

## 关键 K 线事件分析清单

### 急跌、放量下跌、跌破前低
- 比较事件前、下跌中、收盘后以及后续交易日的情绪变化。
- 重点标注恐慌、割肉、爆仓、止损、加仓、抄底与等待二探。
- 判断情绪变化是否与价格、成交额同步；不把同时发生直接解释为因果。

### 长下影、深 V、放量反包
- 记录低点出现时间、收回幅度、收盘位置和成交额。
- 区分盘中喊抄底、收盘后宣布抄底、事后声称抄在最低点。
- 追踪恐惧、踏空、回本退出与新买入意愿的变化。
- “自称买入”不是实际成交证明。

### 二探/回踩
- 以首次插针为事件零点，比较后续 1—8 周的相同来源和采样时段。
- 记录一底、首轮反弹高点、二探日期/低点、间隔、成交额。
- 检验二探时悲观是否仍在但价格不再持续创新低，成交额是否减弱，重新收回关键位置时是否有新增参与。
- 必须保留失败案例：二探后放量下跌、首针后继续创新低、无二探直接反弹、长期横盘。

## 时间曲线规则

- 优先使用页面绝对发帖时间；采集时就记录采集时间，但不可把采集时间冒充发帖时间。
- 只有可靠时间戳且样本足够时才做分钟级曲线；否则按小时或交易阶段展示。
- 每个时间桶显示总帖数、独立作者数、情绪构成、行为意愿、来源构成和时间可用率。
- 原始帖子数与去重作者数分开显示。
- 在曲线上标出关键 K 线、低点、反弹高点、收盘价、成交额与公告时间。
- 相对时间无法可靠换算时不进入精确曲线；缺失数据不填零。
- 时间覆盖偏向某个平台或时段时，明确写出样本范围，不称为全市场情绪。

## 交易员版输出

### 核心判断
3—5 句话说明当前情绪、分歧、可能买卖行为与证据置信度。

### 事件时间线
| 时间（含时区） | K 线/市场动作 | 情绪变化 | 证据质量 |
|---|---|---|---|

### 情绪与行为结构
| 情绪/行为 | 记录数 | 占比 | 相对上一时间桶变化 | 交易含义 |
|---|---:|---:|---|---|

### 关键原话
每类选少量代表性原话并保留原帖链接；默认隐藏用户名，避免断章取义。

### 交易意义
- 支持的情景与反对的情景
- 价格/成交额需要怎样确认
- 下一步观察信号与时间
- 不只凭情绪输出确定买卖指令

### 数据质量与限制
列出时间缺失、相对时间、摘录、重复、平台偏差、作者偏差和样本窗口偏差。

## 最低质量门槛

- 记录总数、去重数、来源数和时间可用率
- 时间精度、时区与发布时间来源
- 原话/链接保留率
- 重复、截断、机器人/营销标记
- 情绪分类口径
- 关键价格与成交额的时间对齐
- 明确区分事实、解释与交易推论

时间或来源受限时，先交付有证据的初步情绪快照，明确缺失项；不伪造时间，也不因时间不完整而放弃现有数据的有用分析。
